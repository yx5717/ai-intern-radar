# AI 实习雷达

作为在校生，面对不同平台、不同公司写法各异的实习 JD，很难快速判断岗位是否真正适合自己。AI 实习雷达把求职过程拆成三个问题：能不能投、值不值得投、应该怎么投。

项目包含 30 条内部样本和 26 条外部盲测样本，覆盖 BOSS 直聘、实习僧、智联招聘和牛客网。网页支持：

- 直接粘贴完整 JD，自动提取岗位、时间、学校、专业和毕业年份要求；
- 覆盖 AI 应用、数据分析、金融投研、财会审税、咨询战略、市场运营、人力资源、商务和供应链等主流岗位方向；
- 上传 DOCX、PDF 或 TXT 简历后，自动识别并回填学校、专业、学历、毕业年份和技能，也可完全手动填写；
- 区分硬约束不满足、加分项不满足、能力缺口和简历表达缺口；
- 生成可直接复制的定制简历提示词；
- 可选接入 DeepSeek、通义千问、豆包、GLM、Kimi 或自定义接口，生成深度分析与改写；
- 支持本地账户，自动恢复求职画像、简历、API 配置和诊断过的岗位。

## 启动

```powershell
.\run_app.ps1
```

浏览器访问 `http://127.0.0.1:8501`。

首次打开网页时先注册本地账户。账户数据保存在 `data/ai_radar.db`，密码只保存加盐哈希，API Key 加密保存且不会进入岗位记录或导出文件。也可以在启动前设置环境变量：

```powershell
$env:AI_RADAR_API_KEY="你的密钥"
```

岗位库只显示当前账户诊断过的 JD；原始样本仅用于评测实验和相似案例检索。不同账户的数据通过用户 ID 隔离，诊断记录仍可从“我的资料”导出或导入。

本地 SQLite 适合个人使用和作品集演示。正式公网部署应改用托管数据库、HTTPS、密钥管理服务，并补充密码找回、登录限流和备份策略。

## 方法

外部样本先由 `rule-baseline-v1` 生成预测并记录哈希，随后才建立人工金标准。被冻结预测不会根据外部答案回写，因此网页中的外部指标可作为跨平台泛化结果，而不是训练集回归成绩。

需要区分的是：冻结预测来自 `scripts/baseline_rules_v1.mjs`（Node 实现），而网页运行时使用的是 `radar_core.py`（Python 实现）。两者是独立实现，外部指标只描述前者，不代表网页引擎的表现。

`scripts/evaluate_python_engine.py` 会在同一批 26 条样本、同一画像下评测 Python 引擎，产出 `data/python_engine_eval_v1.json` 与逐条预测 `data/python_engine_predictions_v1.jsonl`。该产物显式标注为 `internal_regression_not_blind`：Python 引擎是在金标准建立之后编写的，作者已见过答案，因此**只用于回归与迭代，不具备盲测意义**。项目唯一可对外的盲测成绩仍是 `rule-baseline-v1`。

比较前会把金标准中的「职能支持/边界岗位」折叠为当前词表的「职能支持/其他岗位」（`ROLE_ALIASES`），否则同一概念的两种写法会被直接判错。

引擎会给出两类 Bad Case 标记：`边界分类`（岗位归类处于两个方向的边界）和 `摘要正文冲突`（平台自动生成的摘要行与正文最低要求在天数或月数上不一致，例如摘要写「5天／周」而正文写「每周4天以上」）。前者依赖岗位分类质量，后者为独立规则，在外部集上 7 条冲突全部命中且无误报。
